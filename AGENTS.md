# Repository notes for AI assistants

This is a list of papers that apply RSI (recursive self-improvement). The data is in `data/papers.tsv`; the README is generated by a script. Everything in the repository is written in English, including the values in the data.

## Rules

- **Never confirm a paper.** Every paper must be confirmed by a human developer who has checked it against the paper. A confirmer does this by commenting `/confirm` on the paper's issue, after which the workflow writes the confirmation. You may draft annotations, but you must not set `status` to `confirmed`, fill in `confirmed_by` or `confirmed_at`, run `scripts/confirm.py`, or post a `/confirm` comment for anyone.
- **New papers go into an annotation file, not into the data.** On the branch `paper/issue-<number>`, run `python3 scripts/new_paper.py <number>` to create `data/pending/issue-<number>.yml` and fill it in; a pull request changes only that one file. Do not append rows to `data/papers.tsv`.
- **Do not edit the tables in the README by hand.** Edit `data/papers.tsv`, then run `python3 scripts/build_readme.py`.
- **Run the checks before committing.** `python3 scripts/check_data.py` must pass.
- **The data file is `|`-separated.** Text fields must not contain `|`. Column order and allowed values are defined in `scripts/paperlib.py`.
- **Do not add domains, subfields or allowed values on your own.** When something does not fit, raise it for the maintainers to decide.
- **For anything a person must decide, give options and a recommendation.** List the possible choices with the evidence for each, and say which one you recommend and why. Do not ask only open-ended questions, and do not treat your recommendation as settled.

## Skills

- When the user gives a paper link and asks to add it, use the `add-paper` skill in `.agents/skills/add-paper/`. It goes from the link to a pull request; the user then comments `/confirm` on the issue.
- When reading or annotating a paper, use the `paper-reading` skill in `.agents/skills/paper-reading/`.

## Files

- `data/papers.tsv`: all data, one paper per row.
- `scripts/check_data.py`: validates the data and the confirmation rules.
- `scripts/build_readme.py`: generates the README from the data.
- `data/pending/issue-<number>.yml`: annotation file for a paper awaiting confirmation; exists only on its branch.
- `scripts/add_paper.py`: `check`, `open` and `submit` commands that take a paper from a link to a pull request (used by the `add-paper` skill).
- `scripts/new_paper.py`: creates the annotation file for an issue.
- `scripts/render_review.py`: renders an annotation file as the review shown on the issue page.
- `scripts/confirm.py`: records a confirmation; run only by the `/confirm` workflow.
- `scripts/paperlib.py`: columns, allowed values and validation rules.
- `scripts/migrate_to_english.py`: converts files written in the old Chinese vocabulary to the English one.
- `figure/build_figures.py`: generates LaTeX tables and figures for the survey into `figure/generated/` (not committed); see `figure/README.md`.
- `.github/confirmers.txt`: the confirmer list.
- `CONTRIBUTING.md`: step-by-step guide to adding a paper.
